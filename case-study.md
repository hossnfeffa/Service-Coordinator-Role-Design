# Case Study: Modernizing Service Desk Documentation

*Setting: the service desk of a managed service provider (MSP). Organization details are withheld.*

---

## The problem

The service desk's documentation had drifted away from how the team actually worked:

- **Outdated structure.** Documents still described a support tier that had been retired, so responsibilities on paper didn't match reality.
- **Inconsistent terminology.** The same roles appeared under three different naming schemes ("Tier 1", "Level 1", "L1") depending on the document.
- **Duplication and overlap.** Several topics were covered in more than one place, sometimes with conflicting instructions.
- **Obsolete process models.** Some procedures described a workflow the team no longer used.
- **Missing documentation.** Key roles and recurring scenarios had no written procedure; knowledge lived in spreadsheets or in people's heads.
- **No document control.** Many documents had no owner, version, or revision history, which made it hard to tell which copy was current.

## The approach

I followed a repeatable audit framework (detailed in [methodology.md](methodology.md)):

1. **Inventory.** Catalogued every existing SOP, workflow, and reference document, including duplicates and multiple versions.
2. **Assess.** Reviewed each document for accuracy, completeness, and conflicts with other documents.
3. **Standardize.** Settled on a single terminology set and a common document structure before rewriting anything.
4. **Decide per document:** keep, update, consolidate, create new, or retire.
5. **Write for the audience.** Built a full SOP for reference and training, plus a one-page quick reference wherever people need the content under pressure.
6. **Cross-check.** When one document changed, checked related documents for knock-on gaps (for example, a role change in the career matrix had to be reflected in the role-responsibilities document).
7. **Control.** Added ownership, approval, and revision history blocks, and kept a tracker of every document's status.

## Key decisions

| Decision | Reasoning |
| --- | --- |
| Standardize on one tier naming convention | Removes ambiguity, especially for new hires reading several documents |
| Replace a queue-based escalation model with direct, named handoffs | Every ticket keeps a clear owner, so nothing sits unassigned |
| Present contracted after-hours support as a supplementary service, not a tier | Reflects how it actually operates and keeps the tier model clean |
| Pair long SOPs with one-page quick references | Full detail for training, quick reference for live use |
| Align certifications to the work each role actually does | Gives engineers a realistic, motivating path instead of a list of prestigious exams |
| Flag vendor certification retirements instead of swapping them out early | Stays accurate today and signals what changes next |
| Keep originals untouched and track working copies separately | A clear audit trail, and nothing is lost during revision |

## Outcomes

- **15+ documents** audited, rewritten, consolidated, or created
- **Several new SOPs** for roles and scenarios that had never been documented
- **Overlapping documents merged** into single sources of truth
- **One consistent terminology** and structure across the documentation set
- **Document control in place:** ownership, versioning, and a status tracker
- A **structured onboarding program** for new first-line engineers

## What I'd do next

- Set a scheduled review cycle for each document (for example, every 6 or 12 months)
- Link SOPs directly from the ticketing and knowledge-base platforms where engineers already work
- Track adoption signals such as ticket quality scores and escalation accuracy to measure impact
