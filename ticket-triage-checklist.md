# Ticket Triage Checklist

Run this on every ticket before handing it off to a technician.

| # | Check | ✔ |
|---|-------|---|
| 1 | Read the full ticket, including attachments | ☐ |
| 2 | Summary states **who** is impacted | ☐ |
| 3 | Summary states **expected vs. observed** behavior | ☐ |
| 4 | Summary states the **change required** | ☐ |
| 5 | Contact is the real point of contact for this issue | ☐ |
| 6 | Ticket is on the correct board (L1 / L2 / SE / Engineering / Voice) | ☐ |
| 7 | Agreement matches the work, and the default was reviewed rather than just accepted | ☐ |
| 8 | Assigned to a **named** technician matched by skill and client familiarity | ☐ |
| 9 | Workload checked in the Dispatch Portal, not defaulted to the most senior tech | ☐ |
| 10 | Appointment scheduled and logged, if needed | ☐ |
| 11 | Ticket saved cleanly | ☐ |
| 12 | Possible P1? Escalated to the Major Incident process | ☐ |

## Summary template

```
Impacted: <user / group / site>
Expected: <what should happen>
Observed: <what is happening>
Change required: <what needs to be done>
```
